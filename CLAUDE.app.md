# OpenDDA (quantms-web)

OpenDDA's own guidance, imported by the template-owned `CLAUDE.md` (which describes the framework).

**OpenDDA** is quantitative DDA proteomics: label-free (LFQ) and isobaric (TMT/iTRAQ) quantification. The workflow (`src/WorkflowTest.py`, class `WorkflowTest`) runs database search, Percolator rescoring, FDR filtering and ProteomicsLFQ (or the isobaric path), followed by statistics: normalization, imputation, group comparison (volcano), PCA, heatmaps, GO and pathway enrichment.

- Pages: `content/workflow_*.py` (configure, run) and `content/viewer.py`, the **Viewer**: every result of a run is a component (`src/viewer/catalog.py`, one `render(ctx)` per module in `src/viewer/panels/`; component names are stored in saved layouts, never rename one), arranged with the template's view bar (`view_bar`: the preset views in `PRESETS` of `catalog.py`, the first being the default, then the user's own; **+** makes a view, ✏️ orders them and adds up to five runs side by side or one below the other, ⚖️ opens Edit comparison for the first run; `<workspace>/layouts/viewer.json`). Every component of a run shares one Insight state, `scope.shared_state()` (the template's `experiment_state`), so a picked protein, peptide or spectrum stays picked across views; the PSM components keep their row identifiers apart (`PSM_PRIVATE`). Each component is drawn inside `src/viewer/scope.experiment(run_id, index)`, which points `results_helpers` at that run and swaps in the run's own group comparison; widget and Insight keys go through `scoped()` so two runs never share one. The comparison steps (filter, missing values, normalize, test) are in the **Edit comparison** dialog (`src/viewer/comparison.py`), the files of every run under **Export** (`src/viewer/export.py`) below the Viewer.
- Results logic lives in `src/common/` (`protein_table.py`, `spectrum_view.py`, `qc_plots.py`, `samples.py`, `differential.py`, `isobaric.py`, `mass_shifts.py`, `contaminants.py`, `ms2_prediction.py`, ...). Tables go through `show_insight_table(df, name=...)` from `src/common/insight_tables.py`, never `st.dataframe()` on full-size frames.
- Viewer components that compare samples name what they need (`NEEDS` in `src/viewer/catalog.py`): heatmaps two or more samples, the group comparison (group comparison, volcano, GO enrichment) samples in two groups. `src/viewer/analyses.py` reads both from a run's settings (groups as currently set, as the results do); the view bar locks the views a run cannot fill, a note with **Add …** takes such a component's place, and the dialog offers giving the samples groups, processing more files with the run's settings (`follow_up`), or showing a run that has them, alone or side by side.
- PRIDE import (accessions, RAW conversion, SDRF) is `src/pride.py` / `src/pride_ui.py`, next to the template's Import from a link (`src/data_import/`).
- Insight components request a rerun on first render, so never draw them only inside `if st.button(...)`: store the result in `st.session_state` and render outside the button block.
- Deployed as `quantms-ddalfq` (`k8s/overlays/prod`), hosts `opendda.webapps.openms.de` / `.org`. Release tags look like `OpenDDA-1.3.0`.
